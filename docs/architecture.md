# Архитектура приложения

## Поток данных
`chart.json → ChartRegistry/contract → ChartManager → утверждённый dataset → DataClient → Parquet`.
Результат идёт в один общий renderer (ECharts либо HTML table). JSON графика не исполняется как код и не получает DOM, SQL или CSS API.

| Область | Ответственность | Режим |
|---|---|---|
| src/charts/CXX-slug/chart.json | Вопрос, dataset, шаблон, существующие поля | chart |
| src/shared/charts | Валидация, обнаружение, lifecycle, шаблоны | admin |
| src/shared/data/datasets.js | Утверждённые SQL/источники/единицы/ограничения | admin |
| src/shared/data/DataClient.js | Один DuckDB worker, последовательная очередь, регистрация файлов, ограниченный кеш | admin |
| src/shared/filters | Валидируемый период | admin |
| src/layout | GridStack, валидация layouts v1 и workspaces v2, история | admin |
| src/main.js, index.html, src/style.css | Контроллер UI, доступность, общая оболочка | admin |
| scripts, .github, docs | Технические проверки, процессы и методология | admin |

## Пространства
Состояние v2: `{version:2, activeId, spaces:[{id,title,widgets}]}`. Модель `widgets` — дискриминируемое объединение: старый chart-элемент с `chartId` и необязательными `localFilters`, либо `{type:'heading',title,instanceId,x,y,w,h}`. Схема `version:2` и формат старых chart-элементов сохранены без миграции: это обратносуместимое расширение, а не новый файл хранения. Нет заранее заданного набора тематических разделов. На первом открытии создаётся редактируемое стартовое пространство с текущими графиками. Далее источником состава карточек служит сохранённое состояние. Новые графики появляются в каталоге; скрытые/удалённые карточки самопроизвольно не возвращаются.
Активно только одно пространство: другие графики не монтируются и не отправляют запросы. ID пространства/карточки независимы от C-ID. До 40 пространств, 100 карточек в каждом, 40 снимков истории. Сетка хранит 12-колоночные координаты при мобильном отображении.

Локальные фильтры задаются только доверенным каталогом `datasets.js` и сохраняются по `instanceId`, проверяются `LayoutStorage` и SQL-параметризацией. Заголовок является текстовым блоком сетки (через `textContent`), не имеет датасета, запросов или ECharts; наследует общий редактор и историю. Унифицированные таблицы рендерятся общим HTML-рендерером и получают размеры по умолчанию из `ChartRegistry`, но сохранённые пользовательские размеры не сбрасываются.

## Устойчивость
DataClient последовательно выполняет SQL, регистрирует только нужные Parquet, кеширует до 40 результатов по SQL/параметрам/версии данных, освобождает prepared statements. AbortSignal убирает устаревший результат; уже работающий DuckDB SQL физически не прерывается. ChartManager проверяет запрос и экземпляр при каждом ответе, отключает ResizeObserver и уничтожает ECharts при размонтировании. Ошибка одной карточки не останавливает остальные; доступна кнопка «Повторить».

Первая загрузка WASM крупная (десятки МБ до сжатия); это осознанная цена локального SQL. Данных всего 32 файла, в двух текущих графиках читаются три. Новые тяжёлые запросы требуют измерений и при необходимости предагрегатов, не передачи всего факта renderer.

## Границы
Действующий глобальный фильтр — период 2024–2025. Тариф/регион/устройство и прочие разрезы из задания пока не реализованы. Не выводить фиктивные контролы. SQL новых датасетов должен параметризовать значения, подтверждать зерно и исключения тестовых аккаунтов.
Сохранение — localStorage, без сервера синхронизации и без записи в GitHub из браузера. Ошибка хранения видима; импорт валидируется до замены. v1 сохраняется для возможности возврата, повреждённая v2 копируется в recovery-ключ перед следующей записью. Изменение из другой вкладки вызывает предупреждение, автоматического слияния нет.

Контракт и CI защищают от случайных изменений, но не являются sandbox для admin-кода. Обязательная блокировка merge отдельно настраивается в GitHub.
