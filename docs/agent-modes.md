# Режимы ИИ-агентов и границы изменений

Цель — предотвратить **случайное расширение задачи**, а не ограничивать намеренные действия участников. Любой член команды вправе явно выбрать ADMIN; GitHub проверяет пути PR, но не может доказать намерение пользователя.

## Правила интерпретации запроса

| Режим | Включение | Разрешённые изменения |
|---|---|---|
| CHART (по умолчанию) | «Добавь C04», «Улучши C04» | Ровно одна директория `src/charts/CXX-*/**`, включая тесты данного графика |
| BATCH | Явно «BATCH», «Batch», «batch», «режим батч», «пакетный режим», плюс конкретные C-ID | Только перечисленные директории графиков (минимум 2) |
| ADMIN | Явно «ADMIN», «админ», «режим администратора» и конкретная архитектурная задача | Оболочка, движок, общий интерфейс, конфигурация и при необходимости графики |

Слова в пользовательском запросе агент интерпретирует **семантически и без учёта регистра**. Специальная команда в верхнем регистре не нужна. Но нельзя угадывать расширенные полномочия из общей просьбы.

«Сделай дашборд красивым», «Исправь графики», «Оптимизируй всё» без C-ID — **не** разрешение менять оболочку или много графиков. Сначала предложи выбрать конкретный C-ID, явный BATCH с перечнем или ADMIN. Если в запросе названы два графика, но BATCH не назван явно — уточни режим до записи файлов.

**Правило выбора режима фиксируется до изменений**. Не меняй его задним числом, когда CI обнаружил неразрешённые пути. Если для C04 нужен новый тип ECharts, фильтр или общий SQL — останови спорную часть и предложи отдельный ADMIN PR.

## Что разрешено читать

В любом режиме можно читать всё: AGENTS.md, README.md, docs/**, public/data/**, src/shared/**, src/layout/**, src/dashboards/**, другие графики и CI. В CHART/BATCH запрещено *писать* куда-либо кроме целевых каталогов `src/charts/CXX-*/**` — даже документация, тесты в `tests/` и `src/dashboards/overview.json` защищены. Тесты конкретного графика располагать внутри его директории. Один PR = одна область.

Созданный файл `src/charts/CXX-*/index.js` автоматически импортируется реестром. Оболочка сама добавляет **новые** C-ID в макет; удалённые пользователем карточки не должны внезапно возвращаться.

## Машиночитаемый scope в описании Pull Request

GitHub Actions читает **только описание PR**, не текст чата. Поле `mode` нормализуется без учёта регистра и понимает «режим батч», но для проверки лучше использовать канонические значения.

CHART — метаданные необязательны (при их отсутствии разрешён ровно один C-ID):

```text
<!-- ZETFLIX_SCOPE
mode: CHART
charts: C04
-->
```

BATCH — обязателен явный список:

```text
<!-- ZETFLIX_SCOPE
mode: BATCH
charts: C04,C05
-->
```

ADMIN — обязательно указать явно и не перечислять C-ID:

```text
<!-- ZETFLIX_SCOPE
mode: ADMIN
charts:
-->
```

**Не создавай `.changescope.json` в репозитории** — PR-метаданные избегают конфликтов общего файла при одновременных ветках. Шаблон PR содержит CHART и CXX; агент заменяет CXX на реальный ID или удаляет весь блок для CHART.

## CI и ограничения

`scripts/change-scope.mjs` вычисляет **весь diff** от merge-base с `main` до PR HEAD. CHART требует ровно один C-ID, BATCH — точное совпадение с указанными C-ID; оба запрещают изменения оболочки и документов. ADMIN — явный блок в PR. Проверка в `.github/workflows/scope.yml` срабатывает на новые коммиты и правки описания PR.

Для обязательной блокировки merge администратор вручную включает required status check `Scope changes / scope` в GitHub Rulesets/Branch protection. Сам файл workflow не включает эту настройку. Скопивший код или намеренно указавший ADMIN пользователь может обойти ограничения: **эта система не защищает от преднамеренных действий**.
