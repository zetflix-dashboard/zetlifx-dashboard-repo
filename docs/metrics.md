# Единый реестр аналитических метрик

**Источник:** раздел «Определения метрик» из «Инструкция.html». Метрики ниже нормативны для проекта. Не переопределять в файлах отдельных графиков. Для SQL: хранить утверждённую реализацию в одном модуле, доказывать применимость фильтров, указывать дату и зерно.

## Прибыль и деньги
| KPI | Определение | Период |
|---|---|---|
| net_revenue | revenue_subscriptions + revenue_partners + revenue_rentals + revenue_ads − refunds | даты признания каждой составляющей |
| cost_of_revenue | амортизация + доля правообладателей аренды + CDN + комиссии магазинов + эквайринг | месяц затрат |
| gross_profit | net_revenue − cost_of_revenue | месяц |
| gross_margin | SUM(gross_profit) / SUM(net_revenue) | выбранный период; **не** AVG месячных марж |
| operating_profit | gross_profit − support − marketing − product_development − admin | месяц |
| operating_margin | SUM(operating_profit) / SUM(net_revenue) | выбранный период |
| net_cash_flow | фактические поступления минус фактические выплаты | дата платежа, сверка Cash_Control |
| plan_profit | выручка тарифа − сумма Cost_Allocations этого тарифа | тариф × месяц |
| unused_capacity | Cost_Allocations, статус «Неиспользованная мощность» | CDN/поддержка |

Подписки: успешные месячные списания в месяц списания; годовую успешную оплату распределить на 12 месяцев признания с проверкой границ оплаченного периода; возврат по refund_date. Партнёрские начисления по Partner_Settlements.period, аренда по rental_datetime, реклама по Ad_Revenue.period. В контрольных суммах нет тестовых. Поле `PL_Control` — **контроль**, а не автоматическая подмена детального расчёта при сегментации. Несегментируемая общая мера не должна ошибочно реагировать на регион/устройство.

## Подписки, привлечение, удержание
| KPI | Определение |
|---|---|
| subscribers_eom | активные PL1/PL2/PL3 по start_date ≤ конец месяца и (end_date NULL или ≥ конец месяца); без пробных и тестовых |
| paying_subscribers | прямые PL1/PL2 с оплаченным service_period_start..end, покрывающим последний день месяца; при повторном отказе не платящий |
| arpu | revenue_subscriptions / среднее paying_subscribers / число месяцев (для агрегированного периода); за один месяц revenue_subscriptions / paying_subscribers |
| partner_arpu | SUM(Partner_Settlements.amount) / SUM(billed_subscribers) |
| trial_conversion | завершившиеся до среза пробные с is_converted / все завершившиеся; по trial_start_date; прямые |
| churn_rate | окончания кроме «Смена тарифа» за месяц / подписчики на конец предыдущего месяца, PL1/PL2/PL3 отдельно |
| involuntary_churn_share | окончания «Неуспешная оплата» / все окончания кроме смены тарифа; PL1/PL2 |
| retry_recovery | первые отказы, спасённые успешной повторной попыткой / все первые отказы; считать по циклу списания, не по произвольным соседним событиям |
| cac | маркетинговые расходы канала / число пользователей с первой платной подпиской из этого канала; отдельно CAC регистрации |
| retention_month_n | пользователи когорты с платной подпиской через N месяцев после первой оплаты / размер когорты; будущие месяцы NULL |
| observed_customer_value | успешные списания + аренда − возвраты пользователя за наблюдаемое окно; прямые, по первой платной подписке |
| ltv_estimate | ARPU × gross_margin / средний месячный churn; приблизительная модель, рядом с наблюдаемой ценностью |

## Контрольные условия и особые случаи
- Истина о зерне берется из `docs/dataset.md` и фактической схемы Parquet; любые JOIN 1:N с несколькими фактами без предагрегации запрещены.
- Денежные суммы decimal/RUB, исключения тестовых и неуспешных списаний обязательны. Для дробей не AVG(ratio), а SUM(num)/SUM(den) если методика не требует иного.
- Отсутствующий знаменатель: NULL/«нет данных», не 0% и не Infinity. Ненаблюдаемые когорты — NULL.
- RFM нельзя строить на партнёрских подписках. PL4 — аренда, не абонентская база.
- Сверка каждый месяц 2024–2025: `net_revenue`, `cost_of_revenue`, `operating_profit` ↔ `PL_Control`; `net_cash_flow` и балансы ↔ `Cash_Control`. Для отклонений — таблица: месяц, KPI, факт, контроль, дельта, причина. Сравнивать одинаковую дату признания и зерно.
- Зафиксировать тест на цену с 01.03.2025, годовую подписку, возврат, повторное списание, ABC unused capacity, отсутствие двойного счёта, фильтр PL3/PL4, несуществующие будущие месяцы.
