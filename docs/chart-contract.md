# Декларативные графики

Один каталог `src/charts/CXX-slug/`, обязательный `chart.json`, необязательный `README.md`. Регистрация автоматическая через Vite glob. Исполняемые модули не загружаются; build-валидатор запрещает дополнительные файлы и symlink. JSON до 30 КБ, до 6 серий/12 столбцов; результаты до 5000 строк. Общий renderer и контракт — admin-область.

```json
{
  "id": "C03",
  "title": "Выручка и операционная прибыль",
  "question": "Как меняются показатели по месяцам?",
  "dataset": "financialMonthly",
  "template": "combo",
  "dimension": "period",
  "series": [
    { "field": "net_revenue", "type": "bar" },
    { "field": "operating_profit", "type": "bar" },
    { "field": "margin_pct", "type": "line" }
  ]
}
```

| Шаблон | Обязательная конфигурация | Ограничения |
|---|---|---|
| line | dimension, series с field | Линии без сглаживания и соединения NULL |
| bar | dimension, series с field | Столбцы с общей палитрой |
| combo | dimension, series с field и type: line/bar | Не больше двух разных единиц на осях |
| scatter | числовая dimension, числовые series, необязательное pointLabel (текст) | Не подменять категорией числовую ось X; название точки — из проверенного датасета |
| pie | категориальная текстовая dimension, одна числовая series | Сумма по категориям, доли от суммы; интерактивная таблица значений |
| table | columns: массив имён полей, необязательные columnBars и totals: списки числовых полей | Не задавать dimension/series; мини-бары нормализуются отдельно по столбцам; итоги только для явно аддитивных полей |
| tree | текстовые dimension (ID узла), parent (ID родителя), одна числовая series; необязательное pointLabel | Один корень с NULL в parent, до 200 узлов, без циклов. Значения узлов задаёт источник |
| waterfall | текстовые dimension (шаг), stepType (поле с total/delta), одна числовая series | Первый и последний шаги — total; delta — изменение со знаком. Итоги показываются от нуля |
| funnel | текстовая dimension (этап), одна неотрицательная series | Этапы в порядке источника. Срез по каналу — через одобренный локальный фильтр |
| heatmap | dimension (X), category (Y), одна числовая series | Одна строка на пару X/Y, NULL оставляет ячейку пустой. Для retention период наблюдения задаёт источник |
| indicator | Одна числовая series без dimension; необязательная aggregation | Без агрегации — ровно одна строка. Агрегация только sum, avg, min, max; сумма процентов запрещена |
| sankey | dimension (источник), target (назначение), одна числовая series; необязательные sourceTitle/targetTitle | Неотрицательные перетоки, уникальные пары, до 100 связей и 12 сегментов с каждой стороны |

Тип серии задаётся явно только в `combo`. Произвольные параметры ECharts, CSS, HTML, SQL и функции запрещены. Заголовок до 90, вопрос до 300 символов. Строки таблицы выводятся через textContent, подсказки ECharts — richText.

Дополнительные поля новых шаблонов содержат имена полей утверждённого источника. Примеры фрагментов деклараций для будущих источников:

```json
{ "template": "tree", "dimension": "node_id", "parent": "parent_id", "pointLabel": "label", "series": [{ "field": "amount" }] }
{ "template": "waterfall", "dimension": "step", "stepType": "kind", "series": [{ "field": "amount" }] }
{ "template": "funnel", "dimension": "stage", "series": [{ "field": "users" }] }
{ "template": "heatmap", "dimension": "month_of_life", "category": "cohort", "series": [{ "field": "retention_pct" }] }
```

Примеры новых контрактов (имена датасетов и полей приведены **условно**; без утверждённого SQL эти графики не регистрируются):

```json
{ "template": "indicator", "series": [{ "field": "amount" }], "aggregation": "sum" }
{ "template": "sankey", "dimension": "segment_from", "target": "segment_to", "series": [{ "field": "users" }], "sourceTitle": "Январь 2024", "targetTitle": "Декабрь 2025" }
```

**Индикатор.** Число выводится крупно с форматированием согласно единице поля и цветом акцента общей темы. Заголовок, ID, информация об источнике, фильтры, переключение в таблицу и состояние ошибки остаются стандартными элементами карточки. Для нескольких строк агрегатор обязателен. `sum` разрешён для аддитивных чисел, но валидатор запрещает суммировать проценты; корректность других агрегатов по зерну подтверждается владельцем метрики. Значение `0` не скрывается, `NULL` не превращается в ноль.

**Sankey (перетоки).** Источник должен возвращать уже агрегированную таблицу `segment_from × segment_to → users` с одной неотрицательной числовой величиной для каждой пары. Разные стороны получают отдельные идентификаторы даже при одинаковых названиях сегментов. Цвет потока наследуется от исходного сегмента; кнопки «Все» и сегменты управляют подсветкой, а не фильтруют и не пересчитывают факты. Подписи этапов берутся только из `sourceTitle`/`targetTitle` либо из каталога полей, не из произвольного кода. При узкой ширине кнопки прокручиваются внутри карточки. Табличный режим сохраняет исходные пары и значения без потери нулей. Отрицательные потоки, пропущенные категории, дубли пар и слишком большие графы отклоняются. **В текущем каталоге данных нет утверждённого источника переходов RFM между датами:** эти две картинки являются референсами оформления, а не доказательством наличия таких метрик.

Источник возвращает шаги моста и воронки в порядке отображения. Мост сохраняет фактические итоги из источника и показывает разрывы сверки на уровне линий между шагами. Для тепловой карты порядок строк и столбцов определяется первым появлением категорий. Возвращайте `NULL` для будущих ячеек и включайте все требуемые метки обеих осей в результат.

В общей таблице заголовки сортируют по исходным значениям при нажатии или с клавиатуры. Повторное нажатие меняет направление. Пустые значения остаются в конце. Строка «Итого» идёт после данных и прокручивается вместе с ними. Мини-бары имеют отступы даже на максимуме. Сортировка действует в пределах одной карточки и сохраняется при изменении фильтра или переключении представления.

## Доступные источники
- `financialMonthly`: period, net_revenue (₽), operating_profit (₽), margin_pct (%). PL_Control, месяц признания. Это контрольные итоги; доступен локальный фильтр квартала поверх глобального периода, но сегментация и независимая сверка по фактам отсутствуют.
- `advertisingMonthly`: period, fill_pct (%), ecpm (₽). Ad_Inventory и Ad_Revenue, месяц показов. Не является полным C18: доход на пользователя PL1 ещё не реализован.

Дополнительно доступны `originalsViewing` (C15: часы просмотра оригиналов), `titleCostPerHour` (C14: амортизация за час просмотра тайтла), `rfmSnapshot` (C20: RFM на фиксированную дату 31.12.2025, общий период не применяется). Новые графики выбираются в каталоге и не добавляются принудительно в пользовательские пространства.

Точный каталог полей, источников и SQL — `src/shared/data/datasets.js`. Во всех действующих источниках параметры — начало/конец месяца из periodFrom/periodTo. Другие глобальные фильтры пока не реализованы.

C20 использует расширенный девятиколоночный шаблон: помимо сегмента, пользователей и платежей — доли, платежи на пользователя, средние оплаченные месяцы, средние дни с просмотра и пользователей без просмотров. В итоговой строке суммируются только аддитивные показатели и доли. C03 имеет локальный фильтр квартала (I–IV или все) по существующему месячному PL_Control без выдуманного тарифного разреза. В общей оболочке вместо вторичной подписи источника графика показан бледный C-ID рядом с заголовком.

Новая комбинация уже утверждённых полей доступна в chart. Новый расчёт, новый набор данных, новый тип визуализации или новая семантика фильтра — admin. Если шаблона нет, предложить существующий вариант или отдельное расширение, не обходить валидатор.

## Локальные фильтры

Источник (`src/shared/data/datasets.js`) в admin-режиме утверждает `localFilters`: ID, подпись и строгий список вариантов (первый — «Все»). SQL использует только параметрические `?`, порядок параметров: общий период, затем локальные фильтры в порядке источника. `chart.json` может указать только `localFilters: ["genre"]` или другой уже одобренный ID из источника. Выбор хранится в конкретной карточке рабочего пространства, не воздействует на другие карточки; старые макеты без выбора получают опцию «Все». Некорректный фильтр отклоняется валидатором. Фиксированная RFM-сегментация C20 не поддерживает локальные фильтры до утверждения отдельной методики знаменателя.

## Общие правила отображения
Шрифт system-ui, спокойная контрастная палитра, одинаковые отступы/оси/легенды и денежные/процентные форматы. Не использовать smooth для финансовых рядов. Сохранять NULL и отрицательные значения; ноль не заменяет отсутствие данных. Цвет дополняется типом линии/паттернами. Каждая диаграмма переключается в семантическую HTML-таблицу. Карточка показывает источник, вопрос и ограничения через «О данных».
