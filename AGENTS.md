# Зетфликс

Командный дашборд на Vite, JavaScript, ECharts и DuckDB-Wasm. Данные хранятся в Parquet и запрашиваются SQL в браузере. Целевая публикация — GitHub Pages.

## Перед изменением

- Прочитай [README.md](README.md) и ближайший AGENTS.md для затронутой папки.
- Для SQL, фильтров и расчётов прочитай [docs/metrics.md](docs/metrics.md). Проверяй фактическую схему Parquet и определения в инструкции к датасету перед написанием запроса.
- Начинай задачу с актуальной основной ветки. Делай изменения в отдельной ветке и открывай pull request. В PR укажи, что изменилось в графике, какие фильтры затронуты и как проверены цифры.

## Структура и границы изменений

- В src/charts/ хранится по одному модулю на график. Общие фильтры, стили, доступ к данным и повторно используемые определения метрик принадлежат общему коду.
- Используй общий контракт графиков и параметризуй значения фильтров через интерфейс запросов. Для неприменимого фильтра явно укажи это в графике.
- Считывай исходные Parquet из public/data/. Для нового графика по умолчанию выполняй SQL при запросе. Общие определения можно вынести в переиспользуемое SQL-представление.
- Правки определения метрики, схемы данных, инструкций, проверок и публикации выделяй в PR и явно отмечай для ответственного за проект. Если обычная задача графика требует такой правки, объясни зависимость в PR.

## Проверки

- Запусти команды, определённые в package.json и CI, когда они появятся. Для графика проверь состояние по умолчанию, изменение применимых фильтров и пустую выборку.
- Сверь изменённый расчёт на известном срезе. Для финансов проверяй сопоставимые итоги по контрольным таблицам. Сообщи, какие проверки реально выполнены и какие требуют данных или запуска сайта.
- Для Pages проверяй ссылки на Parquet и другие ресурсы на пути репозитория, используя базовый URL Vite.
